# Restic Backup Setup для MeshCentral

Плагин добавляет кнопку «Настроить бекап» в сводку устройства. Он создаёт Windows EXE из компонентов Restic на сервере Linux (в том числе в Docker), передаёт его через файловый канал агента и запускает инициализацию от имени службы агента. Серверу не нужны Windows, PowerShell, компилятор, внешние npm-пакеты или сетевой доступ к клиенту помимо MeshCentral.

## Установка вручную

1. Включите плагины MeshCentral: в `meshcentral-data/config.json` укажите `settings.plugins.enabled: true` и добавьте `"list": ["restic"]` в `settings.plugins`. Если список уже существует, добавьте в него `"restic"`, сохранив остальные имена.
2. Скопируйте содержимое этой папки в `meshcentral-data/plugins/restic/` на сервере. Файл `restic.js`, `builder.js`, `launcher.exe` и каталог `assets` должны находиться непосредственно внутри папки `restic`.
3. Перезапустите MeshCentral, заново откройте веб-интерфейс и перейдите в сводку компьютера.

В Docker каталог `meshcentral-data` должен быть подключён постоянным томом; разместите папку плагина в этом томе и перезапустите контейнер. Плагин не меняет образ контейнера. Учётной записи процесса MeshCentral нужен доступ на чтение файлов плагина.

## Использование

Требуются полный администратор MeshCentral, подключённый Windows-агент, работающий как SYSTEM, и разрешённые файловый канал и выполнение команд. В форме укажите готовые ключи S3, пароль шифрования Restic, путь к файлу базы на компьютере, предел скорости и политику хранения. Плагин автоматически сохраняет настройки S3, API Vaultwarden, идентификатор точки и пароль Restic отдельно для каждого полного администратора в meshcentral-data/restic-settings. На Linux каталог и файлы доступны только владельцу процесса MeshCentral. Файл содержит секреты в открытом виде; защищайте резервные копии данных сервера. Сохраните пароль отдельно для восстановления. Сгенерированный пакет содержит секреты.

Для работы браузер должен оставаться открытым до завершения. Интерфейс показывает передачу и затем результат команды инициализации; сообщение об успешной установке означает нулевой код завершения установщика, а не успешный первый бекап. Проверьте задание и журналы в `C:\restic\<идентификатор>` и выполните тестовый бекап. При обрыве связи результат может быть неизвестен — проверьте компьютер перед повторной установкой.

Файл передаётся в закрытый каталог временных файлов SYSTEM и после завершения установки удаляется. При обрыве возможно сохранение неполного файла `restic-*.exe` в этом каталоге. Пакет временно находится в памяти сервера и браузера; сохранённые по кнопке настройки остаются на диске сервера. Используйте HTTPS для MeshCentral и хранилища. Для S3 плагин использует готовые ключи; автоматическое создание ключей VK Cloud и настройка почтовых отчётов в форме не реализованы. Существующие настройки почты в генераторе автоматически не переносятся.

Файлы `launcher.cs` и `test.js` предназначены для разработки. `npm test` проверяет сборку пакетов и обработчик плагина; для теста полного сценария нужны действующий MeshCentral и тестовый Windows-агент. Сборка Windows-загрузчика при изменении исходника выполняется компилятором .NET Framework с ссылками на `System.IO.Compression.dll` и `System.IO.Compression.FileSystem.dll`.

Кнопка проверки определяет число установленных конфигураций с файлами и число включённых заданий, указывающих на соответствующий backup.ps1. Проверка не запускает бекап и не подтверждает успешность предыдущих копий.

## Vaultwarden

На Linux x64 плагин использует включённый официальный Bitwarden CLI 2026.8.0. В форме укажите client_id и client_secret личного API key учётной записи sokol@kzvs.pro; настройки сохраняются автоматически. Введите мастер-пароль и нажмите «Разблокировать Vaultwarden»: сессия действует 30 минут, мастер-пароль не записывается в настройки. Сервисная сессия даёт доступ к хранилищу этой учётной записи, а не только к папке Vets_Backup. После завершения сессии требуется повторная разблокировка.

Перед сборкой плагин сохраняет пару Restic: идентификатор/пароль в существующую личную папку Vets_Backup и проверяет созданную запись. Существующая запись с другим паролем не перезаписывается. При обрыве или неясном ответе проверьте папку прежде чем повторять операцию. Пароль также находится в конфигурации установленной точки. Не сохраняйте реальные ключи в GitHub.

Кнопка «Журнал» отображает этапы операции и последний вывод установщика на выбранном компьютере. В версиях до 0.3.1 вывод не записывался. Файл последней установки находится в защищённом временном каталоге SYSTEM; он может содержать диагностические данные.
